# J.A.R.V.I.S. Implementation Plan

> For Hermes: implement phase by phase. Each phase ends with a verification gate that must pass (real output, screenshots, audio check) before the next phase starts. Code via Claude Code (Sonnet 5).

Goal: A desktop J.A.R.V.I.S. for Stephen. You talk or type, it answers by voice and text, shows movie-style holographic visuals while it works, has full Gmail + Google Workspace access, and can do anything Hermes can do.

Architecture: Don't build a second agent. JARVIS is a voice and visual shell on top of the Hermes gateway API server (localhost:8642), which already has every tool, skill, MCP server (Linear, Pylon, Notion, Slack, Canva...), memory, the browser, the terminal, and Google Workspace. A small "JARVIS Core" service sits between the UI and Hermes. It handles speech-to-text, text-to-speech, wake word, visual-card generation and confirmation for risky actions. The UI is an Electron app with a Three.js HUD.

Tech stack: Electron + Vite + React + TypeScript + React Three Fiber (WebGL shaders) + Framer Motion + Tailwind | JARVIS Core: Python 3.11 FastAPI + WebSockets (uv venv) | Brain: Hermes gateway `/v1/runs` + SSE events | STT: OpenAI gpt-4o-transcribe (streaming) with local faster-whisper fallback | TTS: ElevenLabs (British butler voice) or OpenAI TTS | Wake word: openWakeWord "hey_jarvis" (free, runs locally) | Tests: pytest, vitest, Playwright (Electron).

## 1. System design

```
┌──────────────────────── Electron app (JARVIS UI) ────────────────────────┐
│  HUD: arc-reactor orb (audio-reactive shader), radial rings, grid,        │
│  scanlines, transcript stream, holo "visual cards", status telemetry      │
│  Mic capture (WebAudio/AudioWorklet)  ·  Speaker playback  ·  Text input  │
│  Global hotkey (⌥Space) · Menu-bar icon · Launch at login                  │
└───────────────▲──────────────────────────────────────┬───────────────────┘
                │ WebSocket (events, audio, cards)      │
┌───────────────┴──────────── JARVIS Core (FastAPI :8765, 127.0.0.1) ──────┐
│  wake word (openWakeWord)  → VAD (silero) → STT (streaming)               │
│  turn manager: barge-in, cancel, steer, session continuity                │
│  Hermes client: POST /v1/runs → SSE events → normalize                    │
│  visual engine: tool events + <jarvis-visual> blocks → typed cards        │
│  safety gate: send/delete/share/pay → confirm card + spoken "Confirm?"    │
│  TTS: sentence-chunk streaming, audio amplitude → orb                     │
│  fast paths: Gmail/Calendar direct reads for instant cards (optional)     │
└───────────────▲───────────────────────────────────────────────────────────┘
                │ HTTP + SSE (API_SERVER_KEY)
┌───────────────┴──────── Hermes gateway API server (:8642) ────────────────┐
│  All tools, skills, MCPs, memory, browser, terminal, Google Workspace     │
│  Dedicated "jarvis" persona (butler tone, concise spoken answers)          │
└───────────────────────────────────────────────────────────────────────────┘
```

Why this shape:
- "Do everything you can do" comes free. Every new Hermes tool or skill shows up in JARVIS with no JARVIS code changes.
- Core stays thin and testable. The UI is swappable (the same WS protocol could later serve a phone/web client).

### Latency budget (voice turn, target under 1.5s to first spoken word on simple questions)
- End-of-speech detection: 300 ms (VAD)
- STT final: 200-400 ms (streaming)
- First LLM tokens: 300-700 ms (fast model for voice turns, e.g. Gemini Flash or Claude Haiku-class)
- First TTS audio chunk: 200-300 ms (streamed on the first sentence)
- Tool-heavy turns (Gmail search etc.) speak a short acknowledgement immediately ("Pulling up your inbox, sir.") while the cards animate in.

## 2. Visual language (movie-accurate)

- Palette: deep navy/black `#02060d`, cyan holo `#00d8ff`, soft white `#e6fbff`, warning amber `#ffb347`, alert red `#ff3b3b`. Additive glow and bloom.
- Core orb: a GPU shader "arc reactor" with concentric rotating segmented rings. It pulses with mic input while listening, spins up while thinking, and its waveform follows TTS amplitude while speaking.
- Ambient HUD: faint hex grid, radial tick marks, rotating data rings, scanline and chromatic aberration post-processing, live telemetry (time, weather, unread count, next meeting, CPU/network).
- Typography: Orbitron/Rajdhani for labels, Inter for body text. Text types on with a letter-decode effect.
- Visual cards: panels that fly out of the orb. Each has a projected-glass look with corner brackets and a scan-in animation.
- States: idle, wake, listening, thinking, speaking, awaiting-confirmation, error. Each has a distinct orb animation and sound cue (subtle UI chirps).

Card types (v1):
| Card | Triggered by |
|---|---|
| EmailList (sender, subject, time, unread dot, priority tag) | gmail search |
| EmailThread (full thread reader) | gmail get / "read me the email from…" |
| DraftComposer (editable to/cc/subject/body + Send / Edit / Discard) | draft, reply |
| ConfirmAction (big amber "AUTHORIZE?" panel, voice or click) | send, delete, trash, share, calendar create/delete, any Hermes approval event |
| CalendarTimeline (day/week strip, conflicts in red) | calendar list |
| FileGrid (Drive/Docs/Sheets thumbnails) | drive search |
| DataTable / Chart (bar, line, pie) | sheets, analytics, any numeric answer |
| WebPreview / Screenshot | browser tool, web search |
| ImageCard | generated or retrieved images |
| ToolTrace (live stream of which tools are running, like the movie's rapid-fire diagnostics) | every tool-progress SSE event |
| Markdown / Code | generic rich answers |
| Map | location queries |

How cards are produced (two sources):
1. Automatic: JARVIS Core maps Hermes tool-progress events and tool results to cards, e.g. a `google_api.py gmail search` result becomes an EmailList.
2. Model-authored: the jarvis persona prompt teaches the model to emit ```jarvis-visual``` JSON blocks (schema-validated) whenever a visual helps, such as charts, tables and comparisons. Core strips these blocks from the spoken text.

## 3. Safety model for your email and accounts

- Read-only actions (search, read, summarize, list) run immediately.
- Draft actions create a real Gmail draft and show the DraftComposer. They never send.
- Destructive or outbound actions (send, reply-send, delete, trash, archive in bulk, share, calendar invites to others, anything a Hermes approval event flags) always stop at a ConfirmAction card. JARVIS reads back the recipient and subject and waits for "Confirm" or "Send it" by voice, or a click. It auto-cancels after 60s.
- Deletes go to Trash by default and are reversible. Permanent delete needs an explicit second confirmation.
- Bulk actions (more than 10 messages) show a count and a sample before confirming.
- Everything binds to 127.0.0.1 only. Core-to-Hermes auth uses `API_SERVER_KEY`, and the UI-to-Core WebSocket requires a per-launch token. No inbound ports are exposed.
- Audit log: every executed action goes to `~/Library/Logs/Jarvis/actions.jsonl` (action, target, timestamp, confirmation source).
- Wake word runs locally and audio is sent to STT only after the wake word fires or push-to-talk is pressed. An optional "privacy mode" hotkey turns the mic off entirely.

## 7. Risks and tradeoffs

- Google API enablement and account choice block the email features until Phase 0 is done.
- Voice latency depends on the model. Heavy agentic turns (multi-tool) take 5-30s. JARVIS covers the gap with spoken acknowledgements and live ToolTrace visuals, but it won't be instant for complex tasks.
- Movie-accurate voice: ElevenLabs gets closest (a British male "butler" voice). Cloning Paul Bettany's actual voice isn't something I'll do, since it's a real person's likeness. A similar-sounding stock or designed voice is fine.
- Full "do everything" power means JARVIS inherits terminal and browser access. The safety gate and Hermes approvals are the guardrail, and the confirm-before-outbound rule is non-negotiable in the design.
- Electron adds about 150MB. The alternative is a browser tab at localhost, which is lighter but loses the global hotkey, tray and launch-at-login.
